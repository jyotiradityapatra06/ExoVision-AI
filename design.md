## 1. Executive Summary & Vision

### 1.1 Mission
**ExoVision AI** is an AI-assisted exoplanet candidate screening and transit disambiguation platform. It transforms raw stellar photometry from NASA space telescopes (Kepler, K2, TESS) and user-supplied light curves into rigorous, explainable exoplanet candidate screening assessments using Astropy, Box Least Squares (BLS), and Random Forest classification.

The current frontend implementation is functional and achieves phase goals, but it suffers from:
1. **Design System Fragmentation:** Multiple overlapping design phases coexist in a monolithic 121 KB `globals.css` file containing redundant, conflicting styles (Phase 1 Stitch HUD, Phase 4 application shell, Phase 4G observatory styles, and Phase 2 hero overrides).
2. **Component Disconnection:** Multiple redundant button styles (`Button`, `.btn-primary`, `.obs-aperture-cta`, `.landing-button`), card wrappers (`Card`, `.surface-card`, `.mission-panel`, `.telemetry-card`, `.results-metric-card`), and disparate design tokens.
3. **Data Visualization Limitations:** Photometric light curves are drawn using simple 2D canvas routines without interactive pan/zoom physics, transit model overlays (e.g., limb-darkened Mandel-Agol or BLS trapezoid fits), residuals analysis ($O - C$), or frequency-domain BLS periodogram power spectra.
4. **UX & Scientific Workflow Friction:** A lack of client-side pre-flight file validation, lack of instant waveform previews on upload, basic search results for NASA MAST, and an underutilized results workspace that fails to expose the full depth of astronomical diagnostics generated by the backend.

### 1.2 The Redesign Vision: "Deep Space Observatory" (DSO)
The new frontend will feel like an ultra-premium, tactile, precision scientific command bridge—blending the ergonomic minimalism of Linear and Vercel with the high-density scientific instrumentation of the James Webb Space Telescope (JWST) Science Operations Center and NASA Eyes.

## 2. Codebase Audit & Architectural Pain Points

### 2.1 The CSS Monolith (`globals.css` — 121,012 bytes, 1,165 lines)
An audit of `frontend/src/app/globals.css` reveals that 4 different design initiatives were layered on top of each other over time:
* **Lines 5–72:** Custom base variables (`--obs-void`, `--obs-deep`, `--stellar-cyan`, `--transit-amber`).
* **Lines 73–270:** Cyberpunk/Stitch HUD rules (`.hud-glass`, `.hud-border`, `.corner-bracket-tl`, `.eyebrow`).
* **Lines 271–454:** First-generation landing page styles (`.landing-page`, `.product-grid`, `.pipeline-sequence`).
* **Lines 455–600:** Application shell and dashboard table styles (`.auth-shell`, `.app-sidebar`, `.dashboard-workspace`).
* **Lines 601–750:** Phase 4E/F results workspace and reports archive styles (`.results-workspace`, `.report-card`).
* **Lines 751–912:** Phase 4G observatory visual system with conflicting `:root` redefinitions and `!important` tags.
* **Lines 913–1165:** Phase 2 "First Contact" patches adding `.landing-hero-video`, `.ose-card`, and `.obs-console-header`.

**Impact:** Unmaintainable CSS specificity wars, unpurgeable class definitions, style drift, duplicate CSS variables, and slow build/parse times.

### 2.2 Component Hierarchy Inconsistencies
* **Buttons:** `src/components/button.tsx` defines a `<Button>` component with Tailwind classes (`bg-primary`, `font-label-caps`). However, `DashboardPage` uses `.obs-aperture-cta` and `.btn-secondary`, `UploadDropzone` uses `.intake-submit`, and `ReportsPage` uses inline CSS classes.
* **Cards:** `src/components/card.tsx` provides `<Card>` with `hudCorners` and `glow`, but it is bypassed in almost every major route (`/dashboard`, `/upload`, `/reports`, `/results/[id]`) in favor of ad-hoc CSS classes.
* **Navigation:** `src/components/navbar.tsx` is an application sidebar that collapses into an icon strip on tablet and a drawer on mobile, while `LandingNav.tsx` is a completely separate top navigation bar with different branding elements.
* **Chart Rendering:** `InteractiveLineChart.tsx` renders 2D canvas directly inside the component using raw imperative 2D context calls, with manual coordinate projection and rigid mouse events that lack touch gestures, multi-touch pinch-to-zoom, and smooth interpolation.

## 3. Design Philosophy & Design Tokens ("Deep Space Observatory")

### 3.1 Design Principles
1. **Photometric First:** Data points and scientific light curves are the heroes. Backgrounds must be ultra-dark and optical (void black with subtle deep nebula undertones), avoiding distracting star animations where measurements take place.
2. **Sub-Pixel Precision:** High-density typography, micro-labels, hairline border strokes (1px with 8%–18% opacity), and tabular monospace numerals for all numerical values.
3. **Calibrated Semantic Palette:** Colors are not decorative; they denote astrophysical meaning (e.g., Cyan = verified photometry & active instrument; Amber = transit depth & periodic drop; Violet = Random Forest ML inferences; Emerald = Candidate flag; Ruby = Non-detection or critical false-positive anomaly).
4. **Physical Tactility:** Micro-interactions (0.16s ease curves), subtle radial ambient lights following pointer motion, and crisp glassmorphic panels with backdrop filters.

## 4. Design System Component Library (`src/components/ui/`)

Replace ad-hoc CSS classes and inconsistent UI primitives with a single, production-grade component kit located in `src/components/ui/`:

### 4.1 Surface Primitives: `ObservatoryCard`
A versatile glassmorphic container supporting 4 visual modes:
* `variant="flat"`: L2 background for secondary telemetry grids.
* `variant="elevated"`: L3 surface with subtle top-highlight hairline for focal dashboard cards.
* `variant="interactive"`: Hover elevation with subtle cyan perimeter glow and cursor translation.
* `variant="reticle"`: Optical observatory corners (subtle SVG corner brackets for scientific instrument panels).

### 4.2 Action Controls: `PrecisionButton`
Unified button replacing all 5 previous button styles:
* `variant="primary"`: Solid starlight background with cyan drop-shadow and dark text for dominant actions (e.g., "Start Analysis", "Download Report").
* `variant="secondary"`: Semi-transparent optical glass with hairline slate border, lighting up on hover.
* `variant="danger"`: Muted crimson border and text for revocations or failed analysis retry actions.
* `variant="ghost"`: Borderless, minimal icon-friendly button for toolbar actions.
* Includes integrated loading spinner state, shortcut keyboard badge display, and soundless click haptic animation (`active:scale-[0.98]`).

### 4.3 Informational Indicators: `StatusBadge` & `ConfidenceGauge`
* **`StatusBadge`:** Micro-pills with pulsating status indicator dots:
  * `processing`: Spinning cyan gyro icon with animated wave sweep.
  * `candidate`: Emerald glowing indicator with `ORBITAL CANDIDATE FLAG`.
  * `non-detection`: Muted amber indicator with `NO TRANSIT DETECTED`.
  * `failed`: Crimson icon with `EXECUTION FAILED`.
* **`ConfidenceGauge`:** Circular or linear dual-phase meter displaying Random Forest score (`0.0%` to `100.0%`) with color gradient from Slate $\to$ Cyan $\to$ Emerald, accompanied by the mandatory scientific caveat tooltip.

### 4.4 Inputs & Selectors: `ApertureInput` & `SegmentedControl`
* Darkened `#050911` input field with monospace numbers, custom clear button, file drop targets, and illuminated cyan focus ring.
* Sleek segmented control tabs with Framer Motion layout transition spring animations for switching views (e.g., Raw Photometry vs. Phase-Folded vs. Periodogram).

### 5.1 High-Performance Rendering Engine
* **LTTB (Largest-Triangle-Three-Buckets) Downsampling:** Kepler and TESS long-cadence light curves contain 10,000 to 70,000+ photometric samples. To guarantee butter-smooth 60 FPS pan/zoom without freezing the browser thread, implement a background WebWorker running LTTB decimation to dynamically reduce visible screen points to 1,500–2,500 points when zoomed out.
* **Canvas2D / WebGL Hybrid:** Use high-DPI-aware Canvas2D with sub-pixel rendering for high frame rates, responsive resize observer handling, and crisp Retina displays (`window.devicePixelRatio`).
* **Interactive Tooltip HUD:** Hovering over any data point displays exact BJD timestamp, relative flux, phase, and local standard deviation $\sigma$.

### 5.2 Transit Model Fitting Overlay
* In addition to raw binned scatter points, overlay a smooth **fitted transit model line** (calculated from detected Period $P$, Duration $\tau$, Depth $\delta$, and ingress/egress ratio).
* Provide interactive toggles:
  * `Raw Points` (low opacity scatter cloud).
  * `Binned Points` (phase-binned median flux with error bars).
  * `Model Transit Curve` (solid cyan or amber line).
  * `Residuals Toggle` ($O - C$ flux error display).

### 5.3 BLS Periodogram Spectral Chart
* Display the Box Least Squares periodogram: Trial Period (days) on x-axis vs. BLS Spectral Power / SNR on y-axis.
* Highlight the top peak with a vertical dashed marker line and label ($P = 3.5225\text{ d}$, $\text{SNR} = 18.2$).
* Highlight potential harmonic frequencies ($P/2$, $2P$, $3P$) with muted amber markers to help researchers detect eclipsing binaries with alternating depths.

#### Detailed Quadrant Specifications

##### Quadrant 1: Full-Baseline Light Curve Viewer
* Interactive canvas renderer displaying normalized flux over time (BJD).
* Mini time-scrubber / minimap below the chart for navigation across long baselines.
* Vertical transit markers showing where periodic transits occur along the time axis.
* Toolbar: `Zoom In`, `Zoom Out`, `Reset Scale`, `Toggle Outlier Rejection`.

##### Quadrant 2: Phase-Folded Transit Visualizer
* Displays relative flux folded on the detected period from phase $-0.5$ to $+0.5$, centered at transit phase $0.0$.
* Shows binned median flux dots (amber) with individual observation scatter points (faint slate dots).
* **Fitted Model Curve:** Solid cyan line displaying the BLS box or Mandel-Agol model fit.
* Interactive measurement markers: Visual calipers indicating transit depth $\delta$ and transit duration $\tau$.

##### Quadrant 3: Frequency Periodogram & Residuals
* **BLS Periodogram:** Spectral power curve showing trial periods from 0.5 days to 30 days. Peak detection point marked with an alert badge.
* **Residuals Plot ($O - C$):** Sub-strip displaying the difference between observed flux and model fit to demonstrate that no systemic curvature was missed.

##### Quadrant 4: Explainable AI & False Positive Disambiguation
* **Confidence Gauge:** Visual arc gauge displaying the Random Forest model score.
* **Ranked Feature Importance:** Horizontal attribution bars showing which features drove the classification:
  * `transit_snr` (Signal strength relative to noise).
  * `depth_consistency` (Consistency of transit depth across cycles).
  * `symmetry_score` (Transit ingress vs. egress symmetry).
  * `odd_even_depth_difference` (Crucial test: checks if odd and even transits differ in depth, identifying eclipsing binary stars).
  * `secondary_eclipse_indicator` (Checks for occultation of a companion star).
* **Evidence Cards:**
  * *Supporting Evidence:* Bulleted domain factors supporting candidate consideration.
  * *Cautionary Flags:* Bulleted caveats (e.g., stellar variability, high noise ratio).

##### Telemetry Registry Table:
* Formatted data table with 12+ parameters: Orbital Period ($P$), Transit Epoch ($t_0$), Duration ($\tau$), Fractional Depth ($\delta$), Transit Depth in Parts Per Million ($\text{ppm}$), Signal-to-Noise ($\text{SNR}$), Symmetry Ratio, Number of Transits Observed, Classifier Version.

##### Publication & Export Dock:
* Primary button: `Generate Scientific Dossier (PDF)` (triggers ReportLab automated compilation with verified plots).
* Secondary buttons:
  * `Export BibTeX Citation` (generates formatted LaTeX BibTeX citation).
  * `Download CSV Telemetry` (exports processed time, flux, and phase arrays).
  * `Export Publication SVG` (downloads vector graphic of the phase-folded transit).

## 7. State Management, API Layer, & Performance Engineering

### 7.1 State Management Modernization
* **SWR / React Query Pattern:** Replace imperative `useEffect` polling in `dashboard/page.tsx` and `results/[id]/page.tsx` with declarative data-fetching hooks:
  * `useAnalysisStatus(analysisId)` (auto-polls every 1.5s while `status === 'processing'`; stops when `completed` or `failed`).
  * `useAnalysisResult(analysisId)` (cached once loaded).
  * `useDashboardHistory(page, filter)`.
* **Centralized Error Boundaries:** Graceful error boundary cards for network dropouts, 401 session expirations, and 429 rate limit cooling timers with real-time countdown clocks.

### 7.2 Performance & Memory Optimization
* **OffscreenCanvas & WebWorker Decimation:** For light curves exceeding 20,000 samples, pass data arrays to a WebWorker to perform LTTB decimation. This keeps the main browser UI thread at 60 FPS while zooming or resizing charts.
* **Canvas Memory Cleanup:** Explicitly destroy 2D canvas context references, event listeners, and resize observers in component unmount cleanups to prevent memory leaks during long research sessions.
* **Next.js 16 Bundling Optimization:** Ensure Lucide React icons are imported via path-level tree-shaking and dynamic imports are used for heavy client-only charting components.

## 8. Accessibility (a11y), Dark Mode Ergonomics, & Responsiveness

### 8.1 Accessibility (WCAG 2.1 AAA Target)
* **Contrast Compliance:** All text on dark surfaces must maintain a contrast ratio of at least $7:1$ for body copy and $4.5:1$ for large display headings.
* **Screen Reader Photometry:** All dynamic charts must include hidden, accessible data tables or summary narratives (`aria-label`, `aria-describedby`) describing key data trends, min/max flux values, and candidate detection flags for assistive technologies.
* **Full Keyboard Navigation:**
  * Full focus rings on all interactive chart controls.
  * Keyboard shortcuts:
    * `/`: Focus search input.
    * `R`: Reset chart zoom.
    * `P`: Toggle phase-folded view.
    * `D`: Download PDF report.
    * `Esc`: Close open modals or drawers.

### 8.2 Responsive Layout Strategy
* **Desktop (1280px+):** Full 4-Quadrant analysis workbench with simultaneous raw, phase-folded, periodogram, and ML interpretation panels.
* **Tablet (768px–1279px):** 2-column layout; charts stacked in pairs; collapsible sidebar navigation.
* **Mobile (< 768px):** Single-column tabbed interface where researchers can swipe between `[Raw Photometry]`, `[Phase Folded]`, `[Periodogram]`, and `[AI Evidence]`, with full touch-gesture pinch-to-zoom on charts.
